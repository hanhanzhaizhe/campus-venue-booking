# 接口联调说明

Base URL：`http://127.0.0.1:8080`  
鉴权：`Authorization: Bearer <token>`（登录接口除外）  
时间：`Asia/Shanghai`；日期 `yyyy-MM-dd`；时刻 `HH:mm`  
统一响应：`{ "code": "OK", "message": "success", "data": ... }`

## 登录

`POST /api/auth/login`

```json
{ "username": "stu01", "password": "123456" }
```

账号：`admin` / `teacher01` / `stu01`，密码均为 `123456`。

## 用户端

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/venues` | 仅启用场地，可选 `type`、`campus` |
| GET | `/api/venues/{id}` | 详情（可走 Redis 缓存） |
| GET | `/api/venues/{id}/occupancy?date=` | 开放时间 + 当日 CONFIRMED 占用，只读 |
| POST | `/api/reservations` | 提交预约 |
| PUT | `/api/reservations/{id}` | 本人改约，须提前 2 小时；不换场、不占新配额 |
| GET | `/api/reservations/me?filter=` | `UPCOMING` / `ONGOING` / `ENDED` / `CANCELLED` |
| POST | `/api/reservations/{id}/cancel` | 本人，须提前 2 小时 |

提交示例：

```json
{
  "venueId": 1,
  "date": "2026-09-10",
  "startTime": "10:00",
  "endTime": "11:00",
  "purpose": "组会"
}
```

占用接口只供画格子；**能否约上以提交接口为准**。

### 本人改约

`PUT /api/reservations/{id}`（需登录，改自己的 `CONFIRMED` 单）

```bash
curl -s -X PUT 'http://127.0.0.1:8080/api/reservations/1' \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"date":"2026-09-14","startTime":"14:00","endTime":"15:00","purpose":"组会改期"}'
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `date` | 是 | `yyyy-MM-dd` |
| `startTime` / `endTime` | 是 | `HH:mm`，走现有整点/半点与开放时间规则 |
| `purpose` | 否 | 未传或 `null`：保留原用途；非空白：trim 后写入；`""` / 仅空白：清成 `null` |

窗口与取消一致：开始前 2 小时可改，恰好 2h 允许；已开始、已取消、改他人预约分别 `RESCHEDULE_NOT_ALLOWED` / `RESERVATION_NOT_FOUND`。不改 `venueId`，不占新配额。相邻时段成功，相交 409 `CONFLICT`。

## 管理端（仅 ADMIN，学生调会 403）

| 方法 | 路径 |
|---|---|
| GET/POST | `/api/admin/venues` |
| PUT | `/api/admin/venues/{id}` 启停与信息 |
| GET | `/api/admin/reservations?venueId=&userId=&date=` |
| PUT | `/api/admin/reservations/{id}` 管理端改约，开始前均可 |
| POST | `/api/admin/reservations/{id}/cancel` 开始前即可 |
| GET | `/api/admin/audit-logs` 管理端写操作审计查询 |

无物理删除场地。停用后禁止新约，已有预约不自动取消。

### 管理端改约

`PUT /api/admin/reservations/{id}`（仅 ADMIN；学生/教师 → 403）

```bash
curl -s -X PUT 'http://127.0.0.1:8080/api/admin/reservations/1' \
  -H 'Authorization: Bearer <admin-token>' \
  -H 'Content-Type: application/json' \
  -d '{"date":"2026-09-14","startTime":"14:00","endTime":"15:00","purpose":"调课"}'
```

Body 复用本人改约的 `RescheduleReservationRequest`（`date` / `startTime` / `endTime` 必填，`purpose` 语义相同）。可改任意用户的未开始 `CONFIRMED` 单；不换场、不占新配额。

窗口对齐管理端取消：**开始前均可**（无 2h 限制）；已开始或非 `CONFIRMED` → `RESCHEDULE_NOT_ALLOWED`。冲突 / 相邻规则与本人改约相同。

### 管理端写操作审计

管理端**取消**与**改约**成功后，同事务写入独立表 `admin_audit_log`（只追加）。本人侧路径不记。场地 create/update 审计为二期，本期不做。取消/改约接口**不加** `reason` 入参（库字段留空）。

查询：`GET /api/admin/audit-logs`（仅 ADMIN；学生 → 403）

```bash
curl -s -G 'http://127.0.0.1:8080/api/admin/audit-logs' \
  -H 'Authorization: Bearer <admin-token>' \
  --data-urlencode 'reservationId=1' \
  --data-urlencode 'limit=50'
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `reservationId` | 否 | 按预约 |
| `operatorId` | 否 | 按管理员 |
| `action` | 否 | 如 `RESERVATION_CANCEL` / `RESERVATION_RESCHEDULE` |
| `resourceType` | 否 | `RESERVATION` / `VENUE` |
| `resourceId` | 否 | 与 resourceType 联用 |
| `limit` | 否 | 默认 50，最大 200 |

响应 `data` 为列表，字段：`id`、`operatorId`、`action`、`resourceType`、`resourceId`、`reservationId`、`venueId`、`beforeData`、`afterData`、`reason`、`createdAt`。`beforeData`/`afterData` 是 JSON **字符串**摘要，需自行 parse。

## 常见错误码

| code | HTTP | 含义 |
|---|---|---|
| UNAUTHENTICATED | 401 | 未登录或 Token 无效 |
| FORBIDDEN | 403 | 已登录但无权限 |
| CONFLICT | 409 | 时段与他人相交 |
| DUPLICATE_RESERVATION | 409 | 本人同场同起止已有单 |
| QUOTA_EXCEEDED | 400 | 未结束预约已达 2 条 |
| VENUE_DISABLED | 400 | 场地已停用 |
| CANCEL_NOT_ALLOWED | 400 | 取消窗口外或已开始 |
| RESCHEDULE_NOT_ALLOWED | 400 | 改约窗口外、已开始或非 CONFIRMED |
| OUT_OF_OPEN_HOURS | 400 | 不在开放时间 |

完整用例见仓库根目录 Postman 集合。
