# 面试准备：提问点 / 学习点 / 知识点

对照本仓库「高校场地预约」后端。讲故事用 [面试讲法.md](面试讲法.md)，本文件用来背原理、对追问。

核心一句话：**正确性靠 MySQL 事务 + 行锁；Redis 只缓存场地详情。**

## 二、要掌握的知识点（按本项目用法）

### 1. Java / Spring Boot

- Spring Boot 自动配置、分层：`Controller → Service → Mapper`
- `@Transactional`：提交/回滚边界；`isolation = READ_COMMITTED`
- `@RestControllerAdvice`：业务异常转 HTTP + `{code,message,data}`
- Bean Validation：`@Valid` + `@NotNull` / `@Size`，失败走 `PARAM_INVALID`
- 构造器注入（本项目无字段 `@Autowired`）
- 时区：`Asia/Shanghai`，`LocalDate` / `LocalTime` / `LocalDateTime`，不要混用系统默认时区

**对应代码：** `ReservationService`、`GlobalExceptionHandler`、`application.yml`

### 2. 并发与事务（面试最深的一块）

- InnoDB **行锁** 要在事务里、且锁的是已有行（用户行、场地行），不是「锁一条还不存在的预约」
- `SELECT ... FOR UPDATE`：当前读，读最新已提交数据并加锁
- 隔离级别：
  - **可重复读（RR，MySQL 默认）**：普通 SELECT 是快照读；事务内第一次 SELECT 定快照，后续无锁 COUNT 看不见别人已提交的行
  - **读已提交（RC）**：每次普通 SELECT 都能看到最新已提交数据
- 本项目组合：**事务 RC + 冲突/配额/重复查询带 `FOR UPDATE`**
- 加锁顺序固定：**先用户 `FOR UPDATE`，再场地 `FOR UPDATE`**，降低死锁
- 连接池：Hikari `maximum-pool-size: 30`，给 AC4 的 20 路并发留余量

**对应代码：** `ReservationService.create`、`UserMapper.selectByIdForUpdate`、`VenueMapper.selectByIdForUpdate`

### 3. 领域规则（业务题会问）

| 规则 | 要点 |
|---|---|
| 时间对齐 | 起止必须整点或半点，时长 ≥ 30 分钟，不跨天 |
| 可约窗口 | `start > now`，日期不超过今天 + 7 天 |
| 开放时间 | `[openStart, openEnd)`，超出 → `OUT_OF_OPEN_HOURS` |
| 相交 | `start < otherEnd AND end > otherStart`；相邻（11:00 接 11:00）不算冲突 |
| 配额 | 同一用户 `CONFIRMED` 且 `end_time > now` 最多 2 条 |
| 用户取消 | `now <= start - 2h` |
| 管理员取消 | `now < start` |
| 停用场地 | 禁新约，不自动取消已有单 |
| 状态 | 只有 `CONFIRMED` / `CANCELLED`；「已结束」是查询态：`CONFIRMED && end <= now` |

**对应代码：** `TimeSlotRules`、`ConflictChecker`、`QuotaRules`、`CancelRules`

### 4. MySQL 表与索引

三张表：`user`、`venue`、`reservation`。

- `idx_res_venue_time (venue_id, start_time, end_time)`：冲突查询
- `idx_res_user_status (user_id, status)`：配额、我的预约
- 外键：预约必须指向真实用户/场地
- 没有「同一场地同一时段唯一索引」：时段是区间相交，不是等值，唯一索引防不住交叉重叠，所以用行锁 + COUNT

### 5. Redis（只加速，不算正确性）

- 模式：**Cache Aside**
  - 读：先 Redis，没有再 DB，再回填
  - 写：先更新 DB，再 **删缓存**（不是先改 Redis）
- key：`venue:detail:{id}`，TTL 1 小时
- 占用查询、提交预约 **不走 Redis**；`requireVenue` 仍读库
- Redis 异常被吞掉，回源 DB，预约不受影响

**对应代码：** `VenueCache`、`VenueService.getById` / `update`

### 6. 安全

- 无 Session：`SessionCreationPolicy.STATELESS`
- JWT：HS256，payload 含 `sub=userId`、`username`、`role`，过期 86400 秒
- 请求头：`Authorization: Bearer <token>`
- 密码：BCrypt，不明文
- 鉴权：`JwtAuthFilter` 放在 `UsernamePasswordAuthenticationFilter` 之前
- 授权：`/api/admin/**` 要 `ADMIN`；方法上 `@PreAuthorize("hasRole('ADMIN')")`（Spring 会加 `ROLE_` 前缀）
- 401 未登录 / Token 无效；403 已登录但角色不够；响应都是 JSON，不是 HTML 登录页

**对应代码：** `JwtService`、`JwtAuthFilter`、`SecurityConfig`

### 7. 接口与错误码

- 统一包：`{ "code", "message", "data" }`
- 冲突类用 HTTP **409** + `CONFLICT` / `DUPLICATE_RESERVATION`
- 占用接口只给前端画格子，**能否约上以提交接口为准**（避免缓存/竞态误导）

## 三、要学习的技术点（原理清单）

下面按「项目用到 → 建议补的原理」列，复习时对着搜/看书即可。

### A. 数据库（优先）

1. InnoDB 锁：记录锁、间隙锁、临键锁；RR 下间隙锁如何导致幻读被抑制
2. 当前读 vs 快照读：`FOR UPDATE` / `LOCK IN SHARE MODE` vs 普通 SELECT
3. 隔离级别四种：读未提交、读已提交、可重复读、串行化；分别解决脏读/不可重复读/幻读
4. 事务 ACID；undo log 与 MVCC 大概思路
5. 死锁：循环等待；如何用固定加锁顺序避免
6. 索引：最左前缀；为什么冲突用 `(venue_id, start_time, end_time)` 而不是唯一约束
7. 连接池：获取连接、超时、并发数与池大小关系

### B. Redis

1. 五种基本类型里本项目只用 String
2. Cache Aside vs Write Through vs Write Behind
3. 缓存穿透 / 击穿 / 雪崩（本项目详情有 TTL；预约不走缓存，穿透影响小）
4. 删缓存 vs 更新缓存：为什么删更简单（避免并发写脏缓存）
5. SETNX / Redisson 分布式锁：**能讲清，但本项目正确性不用它**
6. Redis 挂了怎么降级

### C. Spring / 工程

1. Filter / Interceptor / AOP 的顺序和职责
2. `SecurityContextHolder` 如何把登录用户传到 Service
3. CSRF 为何在 JWT 无状态下关掉
4. CORS 是什么（本项目开了 cors）
5. HikariCP 基本参数
6. MyBatis-Plus：`LambdaQueryWrapper`、`.last("FOR UPDATE")` 的含义与 SQL 注入注意（只拼固定字符串）

### D. 安全基础

1. JWT 三段：Header / Payload / Signature；签名防篡改、Payload 可被解码所以不放密码
2. Bearer Token vs Cookie Session
3. BCrypt：盐、不可逆、为什么不用 MD5
4. 水平越权：用户取消只能取消自己的单（`userId` 比对）

### E. 领域建模

1. 半开区间 `[start, end)`：相邻可拼接、长度好算
2. 状态机尽量少：P0 只有两态，避免「已结束」落库导致定时任务
3. 查询态 vs 持久态：ENDED 是 filter，不是列值
4. 校验顺序：便宜的时间规则先做，再加锁，再查配额/重复/冲突

### F. 测试与验收

1. 领域规则单测：不启 Spring 也能测相交/配额/取消
2. 并发验收必须多连接真打 HTTP，Postman 串行测不出 AC4
3. 错误码优先级：配额满时再约同一槽会先返回 `QUOTA_EXCEEDED` 而不是 `DUPLICATE_RESERVATION`（实现顺序如此，被问到要承认）

## 四、面试可能提问（按频率）

回答先说结论，再贴本项目做法。展开细节见 [面试讲法.md](面试讲法.md)。

### 项目与设计

**Q. 做了什么？难点在哪？**  
独占场地预约。难点是并发防超约，不是 CRUD。

**Q. 为什么学生和老师预约权限一样？**  
P0 冻结：角色只区分能不能进管理端；预约规则相同。

**Q. 为什么没有审批流 / 支付 / 签到？**  
有意砍掉。审批会把状态机打复杂；支付要超时关单和 MQ；签到是到场态，和「约上」不是同一问题。

**Q. 占用查询和提交为什么分开？**  
占用给 UI 画格子，提交才是权威。两请求之间别人可能已约上，所以画成空闲仍可能 `CONFLICT`。

### 并发（必问）

**Q. 两个请求同时约同一场地同一时段，怎么保证只有一条成功？**  
同一场地行 `FOR UPDATE`，事务内串行查相交再插入。后到的看到已提交的 `CONFIRMED`，返回 409。

**Q. 为什么还要锁用户？**  
配额是「每用户未结束 ≤ 2」。只锁场地，同一人可以同时约两块不同场地，两条都通过配额检查。

**Q. 第一次压测为什么超约？怎么改的？**  
默认 RR + 事务里先无锁 SELECT 场地，快照定死，后面无锁 COUNT 看不见别人的提交。改 RC，并对配额/重复/冲突加 `FOR UPDATE`。20 路结果：1 成功 19 冲突。

**Q. 为什么不用 Redis SETNX？**  
SETNX 挂了或过期会误放行；多实例只要连同一 MySQL，行锁仍然有效。Redis 在本项目只做读加速。

**Q. 为什么不用唯一索引？**  
冲突是区间重叠，不是 `(venue_id, start, end)` 完全相等。唯一索引挡不住 10:00–11:30 和 11:00–12:00。

**Q. 锁顺序为什么是用户再场地？**  
全局统一顺序，避免 A 锁用户 1 再场地 X、B 锁场地 X 再用户 1 形成死锁。

**Q. 读已提交还会幻读吗？防超约够不够？**  
RC 下两次无锁 SELECT 可能条数不同。本项目靠 `FOR UPDATE` 当前读 + 事务，不靠「可重复读」来防超约。

### Redis

**Q. Redis 挂了预约还能用吗？**  
能。`VenueCache` catch 后回源 DB。

**Q. 更新场地为什么是删缓存而不是改缓存？**  
删更简单，避免「先写缓存再写库失败」或并发写脏数据。下次读 miss 再回填。

**Q. 占用为什么不缓存？**  
占用随预约变，短 TTL 也难和提交强一致；错缓存会误导前端，正确性仍以提交为准，缓存收益小、风险大。

### 安全

**Q. JWT 存在哪？服务端怎么鉴权？**  
客户端带 Authorization。Filter 验签后放入 `SecurityContext`，无服务端 Session。

**Q. Token 被截获怎么办？**  
HTTPS（生产应开）；过期时间；不把敏感信息放 payload。本项目是校园课设，未做刷新令牌和黑名单。

**Q. 学生调 `/api/admin/**` 为什么是 403 不是 401？**  
已经认证，但没有 ADMIN。未带 Token 才是 401。

**Q. 为什么取消要校验是不是本人？**  
防止水平越权：知道别人的预约 id 也不能取消。

### 业务规则

**Q. 相邻时段为什么都成功？**  
半开区间，`end == otherStart` 时 `end > otherStart` 为假，不相交。

**Q. 「已结束」为什么不单独存一列？**  
时间到了就是结束，用 `end_time <= now` 计算，避免定时任务改状态。

**Q. 停用场地为什么不取消已有预约？**  
已生效的约定仍然有效；停用只阻断新约。批量取消是 P1。

**Q. 用户 2 小时、管理员开始前，区别是什么？**  
用户要给场地腾班/打扫留窗口；管理员处理纠纷可以更晚，但不能对已开始的单取消。

### 工程细节

**Q. 为什么连接池 30？**  
AC4 同时 20 个事务拿连接；太小会排队超时，看起来像冲突失败。

**Q. MyBatis `.last("FOR UPDATE")` 安全吗？**  
这里是常量，不是用户输入。不要把请求参数拼进去。

**Q. 全局异常不处理会怎样？**  
Spring 默认 HTML/Whitelabel；前端无法按 `code` 分支。所以统一 `Result`。

## 六、被追问时的边界（诚实说）

| 问 | 答 |
|---|---|
| 多机部署？ | 可以，锁在 MySQL，不依赖单机内存 |
| 分库分表？ | P0 单库；跨库行锁失效，要换方案 |
| 缓存双删 / 延迟双删？ | 场地更新低频，单次 evict 够用 |
| Token 注销？ | 未做黑名单，过期即失效 |
| 重复预约 vs 配额谁先返回？ | 先查配额。满额时同一槽再约会得到 `QUOTA_EXCEEDED` |
| 前端？ | 本仓库只有后端 + Swagger/Postman |
