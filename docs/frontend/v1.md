## 3. 路由与角色守卫

| path | name | 角色 | 页面 |
|------|------|------|------|
| `/login` | login | 公开 | 登录 |
| `/` | — | 已登录 | redirect → `/venues` 或 `/admin/reservations`（ADMIN） |
| `/venues` | venues | STUDENT/TEACHER/ADMIN | 场地列表 |
| `/venues/:id` | venue-detail | 同上 | 详情 + 占用 + 预约表单（ADMIN 也可看，预约走用户接口） |
| `/me/reservations` | my-reservations | 已登录非必须 ADMIN | 我的预约；ADMIN 也可有入口或隐藏 |
| `/admin/reservations` | admin-reservations | **仅 ADMIN** | 管理端预约列表 / 改约 / 取消 |
| `/admin/audit-logs` | admin-audit | **仅 ADMIN** | 审计查询 |

**守卫规则：**

1. 无 token → 除 `/login` 外一律去登录，带 `redirect` query。  
2. `role !== ADMIN` 访问 `/admin/**` → 前端直接拦到 `/venues`，并 `ElMessage`；**禁止**再调 `/api/admin/**`（即使调了也应 403）。  
3. 登录成功：`ADMIN` 默认进 `/admin/reservations`；其余进 `/venues`。  
4. token 存 `localStorage`（key 建议 `cvb_token`）；启动时调 `GET /api/auth/me` 校验，失败清 token。

路由模式：`createWebHistory`（已确认）。

## 4. 页面说明（要点）

### 4.1 登录

- 表单：username / password；调用 `POST /api/auth/login`。  
- 成功：存 `token`、`userId`、`username`、`role`；跳转按 §3。  
- 种子账号（联调文档）：`admin` / `teacher01` / `stu01`，密码 `123456`。

### 4.2 场地列表 / 详情

- `GET /api/venues?type=&campus=`  
- 详情：`GET /api/venues/{id}` + `GET /api/venues/{id}/occupancy?date=`  
- `OccupancyGrid`：**只读**展示；选中空档填入预约表单。文案固定：「能否约上以提交为准」。

### 4.3 预约 / 本人改约 / 取消

- 预约：`POST /api/reservations`，body 与联调一致。  
- 改约：`PUT /api/reservations/{id}`；UI 提示「开始前 2 小时可改」。  
- 取消：`POST /api/reservations/{id}/cancel`；同样提示 2h。  
- `purpose`（已确认简化）：输入空=请求体不带该字段；有内容则传；「清空用途」按钮传 `""`。

### 4.4 我的预约

- `GET /api/reservations/me?filter=`，Tab：`UPCOMING` / `ONGOING` / `ENDED` / `CANCELLED`。  
- UPCOMING 行操作：改约、取消（按窗口禁点并 tooltip）。

### 4.5 管理端预约

- 列表：`GET /api/admin/reservations?venueId=&userId=&date=`  
- 改约：`PUT /api/admin/reservations/{id}`，提示「开始前均可」。  
- 取消：`POST /api/admin/reservations/{id}/cancel`。  
- 复用 `RescheduleDialog`，通过 prop `mode: 'user' | 'admin'` 切 API 与文案。

### 4.6 审计查询

- `GET /api/admin/audit-logs`，筛选项：reservationId / operatorId / action / limit。  
- `beforeData` / `afterData` 为 JSON **字符串**，表格里 `JSON.parse` 后格式化展示；parse 失败则原样显示。

## 5. 接口对接清单

统一：Base `http://127.0.0.1:8080`（开发可走代理）；Header `Authorization: Bearer <token>`；响应 `{ code, message, data }`，`code === 'OK'` 才成功。

| 前端模块 | Method | Path | 备注 |
|----------|--------|------|------|
| 登录 | POST | `/api/auth/login` | 无 token |
| 当前用户 | GET | `/api/auth/me` | 启动校验 |
| 场地列表 | GET | `/api/venues` | |
| 场地详情 | GET | `/api/venues/{id}` | |
| 占用 | GET | `/api/venues/{id}/occupancy` | query `date` |
| 预约 | POST | `/api/reservations` | |
| 本人改约 | PUT | `/api/reservations/{id}` | 窗口 2h |
| 我的预约 | GET | `/api/reservations/me` | query `filter` |
| 本人取消 | POST | `/api/reservations/{id}/cancel` | 窗口 2h |
| 管理预约列表 | GET | `/api/admin/reservations` | ADMIN |
| 管理改约 | PUT | `/api/admin/reservations/{id}` | 开始前均可 |
| 管理取消 | POST | `/api/admin/reservations/{id}/cancel` | |
| 审计 | GET | `/api/admin/audit-logs` | |

`http.ts`：401 清 token 跳登录；403 `ElMessage.error`；业务 `code` 非 OK 用 `message` 提示（如 `CONFLICT`、`RESCHEDULE_NOT_ALLOWED`）。

## 6. 工程约定

| 项 | 约定 |
|----|------|
| UI | Element Plus（按需或全量，首版全量可接受） |
| HTTP | axios |
